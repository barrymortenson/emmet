## Placements, as the validator reads them

`build/placements.json` keeps `{ "schema": 1, "model", "parts": [...] }` and gains two optional keys, which the DSL
writes from 3B on and the validator reads now:

- `allow`: `[{ "rule", "parts": [ids], "reason" }]`, from `m.allow(rule, ids, reason)`. Same effect as
  `[[check.allow]]` in emmet.toml.
- `ground`: `[ids]`, from `m.ground(id)`: the parts the model stands on.

Each part row may also carry `copies`: one `{ "id", "step" }` per entry of `submodel`, the id of that submodel copy and
the parent's step that places it. The validator uses it for disconnected_submodel, step_order, and step_size across
submodels; without it each submodel name counts as one copy. `emmet_core::ldraw::placements` fills it for `.mpd`
files.
