## Limits the conversion meets

Read 2026-11-04. Claude ([vision](https://platform.claude.com/docs/en/build-with-claude/vision)): JPEG, PNG, GIF,
and WebP; 10 MB per image base64-encoded on the API and 5 MB on Bedrock; at most 8000 × 8000 px, and 3,000 px a side
once a request holds more than 20 images; current models downscale past a 2,576 px long edge. OpenAI
([images and vision](https://developers.openai.com/api/docs/guides/images-vision)): PNG, JPEG, WebP, and GIF; up to
512 MB per request; `high` detail fits an image within 2048 × 2048. So every attachment is a JPEG whose long edge is at
most 2,048 px and whose file is at most 3.75 MB (5 MB once base64-encoded): inside every limit above, on every
platform Claude Code may run on.

## Order of work

1. **Clean images in Rust.** `emmet_core::refs`: a JPEG's segments walked and only what a decoder needs kept (the
   frame, the tables, the scans, a bare JFIF header, Adobe's color-transform flag), so every other APPn (EXIF, XMP,
   ICC, the maker notes), every COM segment, and anything after the image's end is dropped before anything is saved;
   the size and dimensions checked against the limits above; the file saved atomically as `refs/<name>-<hash>.jpg`
   when the photo is sent (the composer holds it until then), so the same photo sent twice under one name is one file.
2. **Images in both adapters.** `UserTurn.images` (paths under the project's `refs/`): Claude Code gets a stream-JSON
   user message whose content is the image blocks (base64 JPEG) then the text; Codex gets `turn/start` input items
   `localImage { path }` then the text. Transcripts keep a placeholder with the image's hash, not its bytes.
3. **The app.** `chat_attach` takes the converted bytes and returns the saved ref; `chat_send` takes the refs (each
   checked to be a file in the project's `refs/`); `chat_photo` reads one back for the chat and the compare view. The
   main window's file-drop handler is off, so a drop reaches the page as HTML5 files (no paths cross IPC).
4. **The composer.** Attach a photo (the picker), paste, and drop; each image decoded in the webview (PNG, JPEG, and
   HEIC, which WebKit decodes on macOS), scaled to the long edge, re-encoded as JPEG (which drops every metadata
   block), then cleaned again in Rust. Chips above the message box with Remove. The first use shows one sentence: the
   photo goes to the agent the user picked, under that provider's terms. Attach waits while the agent works or a
   question is open (a photo can't be a card's answer, and a redirect is text).
5. **The doctrine.** Building from a photo: say what it shows and estimate its proportions in studs, state the
   assumptions, ask one question about scale when it's open, and end the turn asking for another angle when one
   photo can't settle the depth.
6. **The compare view.** The photo beside the viewer, which the user orbits to line it up. Opening and closing it never
   moves the camera.
7. **The photo rung.** `emmet eval --rung photo --subject <id>`: `--dry-run` with the fake agents (generated images;
   the fake asks for another angle, gets angle b as the next turn, builds); `--score <project>` reads a hand session's
   project and chat, checks the subject's local images against `subjects.toml`, scores 0 validator errors, the part
   range, the second angle, and the time to the first draft, takes Barry's three rubric scores (0 to 2), and writes
   `docs/evals/<date>-photo.md` with the render and not the photo.
8. **E2E and screenshots**, then Barry's hand check in the app with each agent.
