## What the code has today

From a read of `origin/main` at the start (2026-11-12):

- **Windows.** `fsx::canonical` strips `\\?\` from drive paths only, and nothing tests a path over 260 characters.
  Nothing knows about OneDrive: `write_atomic` renames once, with no retry when a sync client or a scanner holds the
  file. The tests' home and data dirs have plain ASCII names. The trust marker and the bus pipe name hash a path as
  given, with no case folding. The pipe has a user-only security descriptor that no test reads back, and the token
  file's `private` flag does nothing on Windows. CLI detection has fixed folders and finds `node` on PATH only. There
  is no WebView2 version check. A software renderer picks Fast (a unit test), but no E2E reads the pick, and a lost
  WebGL context isn't handled. The viewer reads the pixel ratio once. The Windows title-row menus lack entries
  `docs/design/keyboard.md` promises, and the keyboard spec isn't in the Windows E2E list. CI builds the NSIS
  installer and never installs it.
- **Performance.** `perf.e2e.mjs` asserts the 2,000-part column only, and only on a Mac that isn't a hosted runner;
  the rung columns are in `just bench`'s table, which asserts nothing. Windows has hosted numbers only (no GPU: first
  load 9.0 s, slider 1.9 s, no orbit or animation numbers). No rung 3 model is measured. Start-up is logged by
  `hello.e2e.mjs`; first run is timed only with `EMMET_E2E_REAL=1`.
- **Security.** Most of section 15's rows have tests. Missing: any test that a script in a part name, chat markdown,
  or a model name doesn't run; a capabilities check that fails on a grant with no command; the pipe ACL on Windows.
  To verify and, if real, fix: the chat can start an agent in an untrusted project; the approval policy pre-allows
  reads outside the project and edits to any plain file inside it; a kill ends Python but not what it started;
  gitleaks is skipped on prose-only PRs; the trust secret's file isn't written private.

## What the Windows runs found

Three full runs with the Windows jobs on (43375355954, 43441446952, and the next). Real bugs, each fixed with the
test that found it or would have:

- **The chat started an agent in an untrusted project** (the security review's F-1): `trust.e2e.mjs`.
- **A project past 260 characters** built nothing and said Python was missing ("The directory name is invalid"):
  Windows starts no program in a folder that deep unless long paths are on. Emmet now says the path is too long and
  to move the project (`paths.rs::a_project_under_a_path_over_260_characters`). Emmet's own files are fine at any
  length.
- **The menu bar slid under the view switch** in a 1024 px window: the title row's first column now keeps the
  chip's and the menus' width.
- **A lost graphics context** came back without the room the parts reflect, so the model drew dark (and, asked
  back too early by the first version of the test, not at all): the viewer makes the room again and draws
  (`viewer.e2e.mjs`, comparing the canvas's pixels before and after, on a viewer of its own).
- **Windows' menus** lacked Open recent, Exit, and Full screen (F11), which `docs/design/keyboard.md` lists; the
  clipboard items stay out by Barry's decision (2026-11-13).
- **The dependency audit** was red (rmcp) and its gate didn't stop the job.

What the first run's 7 failing E2E specs came down to, beyond those: Windows baselines never committed (untrusted,
versions, the instructions' 155 pages; 4A's and 4E's halves); a test home with no Downloads folder, which Windows
needs to exist; new projects landing in the runner's own Documents, which Windows finds through the account and
not `USERPROFILE` (the tests now set the projects folder); the redo key (Ctrl+Y); and Windows Server's animations
being off, which the app reads as reduced motion, so the build animation never played. The job now turns
animations on for the suite, and `reduced-motion.e2e.mjs` runs first, with them off: menus, popovers, and dialogs
open and close there (run 43455248406), and the build doesn't animate. In the first run only, the Model and effort
popover stayed open over the window from the chat spec on and covered the buttons later specs clicked; it hasn't
happened since, and reduced motion is ruled out as its cause. Not explained: the chat spec now fails there and
then if it ever stays open again.

Measured on this Mac (M-series, 60 Hz, debug build, 2026-11-13): first load 783, 739, and 748 ms at 184, 478, and
2,018 parts; slider → viewer 544, 622, and 637 ms; orbit and build-animation frames at the display's 16.7 ms; 274
draw calls at 2,018 parts; footprint growth 3.4 % after 100 slider changes; start-up interactive at 528 ms; a real
first run built the Cottage 13 s after Get started. Rung 3's set (165 parts) isn't in the repo until 5A's branch
lands, so it's measured as the size it is: the first column.

## Order of work

1. **Windows** (the most unknowns; each round is a hosted CI run).
   1. CI: the Windows jobs' home and data dirs get a name with a space and non-ASCII letters; the keyboard, panel,
      checks, and first-run specs join the Windows E2E list.
   2. Paths: a project over 260 characters, `\\?\UNC\` paths, case-insensitive trust, recent list, and pipe name.
   3. OneDrive and locked files: `write_atomic` and the library swap retry a sharing violation; the watcher ignores
      attribute-only changes; a project in a folder a sync client holds still builds.
   4. The pipe's ACL read back on Windows, and the token and trust-secret files written user-only.
   5. CLI detection: `node` beside a `.cmd` shim and under Program Files; the folders the current installers use.
   6. The WebView2 version check: a minimum in the installer and at start-up, with a message that says what to do.
   7. GPU: the hosted runner's software renderer picks Fast (E2E); a lost context redraws.
   8. DPI: the viewer follows a pixel ratio change; E2E at 100, 150, and 200 %.
   9. The Ctrl keymap: every Windows row of `docs/design/keyboard.md`, with the title-row menus it names.
   10. NSIS: a script installs per-user without elevation, upgrades over itself, and uninstalls keeping app data
       unless asked; the `nsis` job runs it.
   11. The Windows halves left by 1F, 4A, 4B, 4C, and 4E: screen and dock baselines, the PDF page baselines, the
       chat replay specs.
2. **Performance.** The three part-count columns asserted (rung 1, rung 2, and 2,000 parts), a rung 3 model in the
   bench, start-up and first-run time measured, on real hardware on both OSes; the hosted runners report. Fix what
   misses a budget.
3. **Security review** `docs/security/review-1.md`: every row of section 15 → control → test → result; the
   capabilities audit; the dependency audit; gitleaks over the full history. Fix every high and medium finding, each
   with a test.
4. **The H-10 checklist** `docs/security/windows-pass.md`, sized for about an hour; then Barry's pass, and fixes for
   what he finds, before the PR.
