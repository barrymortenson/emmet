## Design notes

- **Viewer (D-23).** The viewer builds its own scene from `placements.json`. Each unique part loads once through
  `LDrawLoader.parse` from a packed `.mpd` the host builds (the part plus every subpart and primitive it uses, as
  `0 FILE` blocks), so a part is one request, not dozens; ADR 0005 found per-file requests are what make WebView2
  slow. The app asks for all of a model's new parts in one `emmet-lib://localhost/pack?parts=…` request. One
  `InstancedMesh` per (part, color); edges and conditional lines are instanced too (the part's line geometry with
  the mesh's `instanceMatrix`), so a diff only rewrites instance buffers. Color 16 and 24 materials are swapped for
  the bucket's color; a part's fixed colors stay. The camera only moves on `frame()` and `setView()`.
- **Updates.** `update()` loads every new part first, then applies adds, removes, moves, and recolors by Emmet id in
  one synchronous pass, so a frame never shows half a diff. A part the pack can't fully resolve is reported, never
  drawn with holes (ADR 0005).
- **Host.** The run queue spawns `emmet --json run` (the sidecar) on its own thread: latest wins, a superseded run is
  canceled by closing its stdin (`emmet run --cancel-on-eof` kills its Python and exits), and a result whose
  generation is older than the one on screen is dropped. The watcher (notify) sees sources only, debounced 150 ms,
  ignoring editor temp files. Every command and event is typed through tauri-specta; a test fails when
  `apps/desktop/src/bindings.ts` is stale.
- **Paths.** The webview never sends a filesystem path except `open_recent`, which must be in the recents list. The
  `emmet-lib://` protocol resolves names inside the library only, after canonicalizing, with symlinks out refused.
- **Render.** `emmet render` asks the running app over the bus first; if no app has the project open it starts
  `Emmet --render` (a hidden window, ADR 0005) and reads the PNG it writes. The MCP `render` tool returns the same PNG
  as image content. Both report `via: "app" | "render-mode"`.
- **Bus v0.** A local socket (a Unix socket, a named pipe on Windows) named from the data dir, a per-launch token in
  `<data>/bus.json`, NDJSON requests `{v, token, id, type, …}`, `render` and `highlight` messages, and
  `delivered: false` when no app is listening or the project isn't open. 1C hardens it (section 15).
