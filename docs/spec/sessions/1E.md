## OpenAI's requirements → proof

Pages read 2026-10-26: overview, UI/UX guidelines, registration and sign-in, accounts and sessions, models and
inference, Codex app-server, self-hosted VMs, token reference, errors and recovery, preview limitations.

| Page | Requirement | Proved by |
|---|---|---|
| Overview | A stable, opaque `ext_agent_host_id` per host, chosen and persisted before the first sign-in (`urn:uuid:` + UUIDv4) | `chatgpt.rs` `host_id_is_made_once_before_the_first_sign_in` |
| Sign-in | First registration: `client_id=dynamic_agent_client`, `agent_name_hint=Emmet`, the host id | `chatgpt.rs` `first_sign_in_registers_emmet` (the fake checks every parameter) |
| Sign-in | Fresh state, nonce, and PKCE (S256, base64url without padding) per attempt; listener started before the browser | `first_sign_in_registers_emmet`, `each_attempt_is_fresh`; PKCE against RFC 7636's example |
| Sign-in | `redirect_uri` `http://127.0.0.1:<port>/auth/callback` (never localhost), the same in the authorize request and the exchange | the fake compares them; `each_attempt_is_fresh` |
| Sign-in | Scopes `openid profile email offline_access resource.invoke chatgpt.tokens.use.direct`, `resource=https://api.openai.com/v1` | `first_sign_in_registers_emmet` |
| Sign-in | `error=access_denied`: validate state, stop, no exchange | `declined_consent_stops_without_an_exchange` |
| Sign-in | A wrong state is rejected; a registration callback without an issued `client_id` is incomplete; `dynamic_agent_client` is never saved | `callback_problems_are_refused` |
| Sign-in | Reauthorization: the saved issued `client_id`, no `agent_name_hint`, `id_token_hint` and `login_hint`; a callback with a different `client_id` is rejected | `returning_sign_in_reuses_the_registration` |
| Sign-in | Exchange: form POST with the issued `client_id`, code, verifier, the same redirect URI and resource, no secret; `invalid_grant` discards the code and the next attempt reuses the issued client id | the fake checks the exchange; `invalid_grant_on_exchange_keeps_the_client` |
| Sign-in | ID token: signature against OpenAI's JWKS (RS256), issuer, audience = the issued client id, expiry, nonce; `sub` is the identity | `bad_id_tokens_are_refused` (signature, `alg`, issuer, audience, expiry, nonce) |
| Sign-in | A returning account's new ID token must match the selected account before credentials are replaced; a new attempt stays apart from the active account until validated | `returning_sign_in_reuses_the_registration`, `bad_id_tokens_are_refused` (the active account is untouched) |
| Sign-in | `chatgpt.tokens.use.direct` must be granted before inference; a valid ID token alone isn't enough | `plan_permission_declined_keeps_the_sign_in` |
| Sign-in | A protected record per issued client id: identity, tokens, scopes, expiry, saved_at, the ID token for `id_token_hint`; tokens never committed or logged | the record's shape in the fake keychain (`first_sign_in_registers_emmet`); `no_token_reaches_any_output`. Emmet keeps it in the OS keychain, which OpenAI's "protected local … runtime storage" covers (ADR 0011) |
| Accounts | Registrations kept apart, even with one email; distinct stable labels; the active account shown in the picker | `two_accounts_stay_apart`; `chatgpt.e2e.mjs` picker; screenshot |
| Accounts | Switching reuses the selected registration's client id and host id; switching doesn't sign the others out | `two_accounts_stay_apart` |
| Accounts | Sign out: stop requests, revoke (discovery's `revocation_endpoint`, form POST with `token`, `token_type_hint=refresh_token`, `client_id`; an empty 200 is success), then clear the tokens; keep the registration and host id | `sign_out_revokes_and_keeps_the_registration` |
| Accounts | Revocation retries a network failure or 5xx with backoff; unconfirmed, clear locally and say so (disconnect in ChatGPT Settings) | `sign_out_without_confirmed_revocation` |
| Accounts | Refresh near expiry: `grant_type=refresh_token`, the issued client id, `resource`, no `scope`; replace access token, expiry, scopes, and refresh token together | `refresh_replaces_the_token_set` |
| Accounts | Serialize refreshes so two callers don't race a rotating token | `refreshes_are_serialized` (two threads, one token request) |
| Accounts | Tokens never in URLs, logs, or transcripts; an authorize URL with `id_token_hint` is never logged | `no_token_reaches_any_output` |
| Accounts | Link to ChatGPT Settings → Usage | `chatgpt.e2e.mjs`: Manage usage asks the host to open `https://chatgpt.com/settings/usage` |
| App-server | OpenAI's provider block (`env_key="ACCESS_TOKEN"`, `wire_api="responses"`, `requires_openai_auth=false`, `supports_websockets=false`) and `ACCESS_TOKEN` in the child's environment | `agent_codex.rs` `plan_turn` (arguments and environment as the fake recorded them) |
| App-server | `clientInfo.name` matches `agent_name_hint` ("Emmet"), with title and version | `plan_turn` |
| App-server | Token renewal: restart app-server with the new `ACCESS_TOKEN`, initialize, `thread/resume` the saved thread | `plan_token_renews_between_turns` |
| App-server | Only `turn.status` `completed` is success | 1C's `quota_exceeded` and `auth_401` tests (unchanged) |
| Errors | Declined or missing plan permission: keep the sign-in, mark plan use off, offer "enable ChatGPT plan usage" or an API key | `plan_permission_declined_keeps_the_sign_in`; `chatgpt.e2e.mjs` |
| Errors | Enabling later repeats OAuth with the saved client id, the full scope set, and `prompt=consent` (not `force_reconsent`, which waits on OpenAI) | `enable_plan_use_asks_for_consent_again` |
| Errors | Plan errors stop inference and never switch billing silently; the status, code, and request id are kept | `plan_usage_limit` (no restart, no API key); the error text carries Codex's message |
| Errors | `subscription_sharing_usage_limit_exceeded`: pause and link to ChatGPT Settings → Usage, with no inferred reset time | `plan_usage_limit`; the limit card in `chatgpt.e2e.mjs`; screenshot |
| Errors | `not_eligible`, `invalid_user`, the 503s, 401/403 admission: the recovery each names | `plan_error_codes_map_to_their_recovery` (one derived transcript per code) |
| Errors | Refresh errors: unusable refresh token → clear and sign in again with the saved client id; `invalid_client` → configuration error; a network failure never erases credentials | `refresh_errors` |
| Preview | Responses limits (`store: false`, `stream: true`, no `tool_search`) | Codex sets them on this route; Barry's rung 1 run proves Emmet's tools work through it |
| UI/UX | "Continue with ChatGPT" in the approved format (black, 45 px, 12 px radius, the white ChatGPT logo) | screenshots, light and dark, macOS and Windows |
