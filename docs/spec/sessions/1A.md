## Design notes

- **Templates and fixtures.** The cottage template keeps to v0 calls: running-bond walls with interlocking corners,
  a door frame and three windows, a ceiling of plates, a gable roof of 45° slopes, and a chimney outside the back
  wall. Fixture models that must stay broken (the syntax error) are written by their test, since the pre-commit hook
  formats every staged .py file.
- **Trust.** `.emmet/trust` holds sha256 of the install's secret and the project path, so `created_by`, which travels
  with a project, can't be turned into a marker (a review finding; `errors.rs` tests it).
- **Frame (section 08).** DSL x right and y back in studs, z up in plates. LDraw position = (20·y, −8·z, −20·x) in
  LDU, so a 2 × 4 brick (long along LDraw X) at `rot=0` covers x 0–2, y 0–4. The map has determinant +1, so rotations
  stay proper. `tests/fixtures/projects/frame/expected.ldr` is a hand-checked `.ldr` that `tests/it/tests/frame.rs` compares against.
- **Part geometry.** `emmet run` writes `build/part-geometry.json` (body boxes for the parts the model uses) and
  `build/colors.json`. When the model asks for a part that isn't in the file, the DSL finishes the pass, reports the
  missing ids with their call sites, and emits nothing; `emmet run` looks them up in the index (an unknown id is
  `UNKNOWN_PART` with suggestions) and runs again. After a clean delete that is two passes; warm runs are one.
- **Python.** `emmet_dsl`'s sources are embedded in the `emmet` binary. On first use emmet asks uv (the sidecar, or
  `uv` on PATH in dev) for a Python 3.13 venv in app data, writes the wheel from the embedded sources, and has uv
  install it without network access. A stamp file holds the sources' hash, so a newer emmet reinstalls.
- **One core.** The CLI and the MCP server call the same `emmet_core::ops` functions and shape their output only.
